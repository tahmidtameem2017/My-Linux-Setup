# AGENTS.md — niri-setup

## Quick start

```bash
./setup.sh                  # full install (Arch + AUR helper required)
./setup.sh --skip-install   # symlink configs only, skip packages
```

`$NIRICONF` is a placeholder replaced at install time by `setup.sh`. All paths below are written in the "after install" form.

## Key facts an agent would miss

- **niri config is modular KDL**: `config.kdl` includes all other `*.kdl` files via `include`. Add a new file → add `include "file.kdl"` in `config.kdl`.
- **Wallpapers are gitignored**: `wallpapers/` and `niri/wallpapers.kdl` are in `.gitignore`. They are generated at runtime. The active wallpaper is always `wallpapers/workspace.{jpg,png,webp}`.
- **One wallpaper engine**: `swaybg` renders the workspace wallpaper. The blurred `backdrop.*` file is **dead work** and is no longer generated (overview is solid black via `misc.kdl`); it cost ~1.4s per change decoding a 4K PNG a second time for nothing.
- **`scripts/change-wallpaper.sh` edits `niri/config.kdl` directly** (via sed on lines containing `swaybg`), not `niri/wallpapers.kdl`. This is a quirk — the `wallpapers.kdl` file is only used at initial spawn.
- **Alacritty has two profiles, and both are GENERATED**: `default.toml` (tiled windows) and `float.toml` (floating for updater, nmtui, wallpaper selector, Dropdown scratchpad). They are rendered from `alacritty/{default,float}.toml.in` by `scripts/sync-external-theme.py` and are gitignored — **edit the `.toml.in`**, never the `.toml`. They are generated at the SAME paths the hand-written files used to occupy, so nothing had to move: `~/.config/alacritty/alacritty.toml` is still a symlink to `default.toml` (covering bare `alacritty` invocations) and every `--config-file $NIRICONF/alacritty/float.toml` caller still works. Placeholders are `{{FG}} {{BG}} {{CURSOR_TEXT}} {{CURSOR}}` and `{{N_*}}`/`{{B_*}}` for the 16 ANSI slots.
- **Dropdown scratchpad** (`scripts/dropdown-terminal.sh`, `Mod+Grave`): zero-dependency, parks the terminal on the persistent `workspace "scratch"` (declared in `niri/config.kdl`) via niri IPC. Test the full cycle (spawn → park → show → park) and leave it parked.
- **Fuzzel/walker are unbound fallback**: `fuzzel/*.ini` configs and the walker binary stay on disk (rollback only). All live menus go through quickshell: `Alt+Space`/`Mod+Ctrl+Return` → Launcher (app search + pinned Controls section: Quick Settings, Wallpaper, Power, Volume, Clipboard, Calendar, DND — control rows dispatch via `qs` IPC, see `Launcher.qml` header), `Mod+C` → clipboard, `Mod+I`/`Mod+P` → settings. Old bind lines are kept as `//` comments in `binds.kdl`/`binds-quickshell.kdl`.
- **Launcher has an "Open" section** (`components/launcher/providers/OpenApps.qml`, `rows()`+`activate()` shape like MediaActions — pinned, not a `$`-style search provider): one row per **running app** deduped by `app_id`, ordered Controls → **Open** → Bookmarks → Applications, built only on the empty query (so it never duplicates rows in the filtered app list). Identity is the pretty app name, the icon is a **Nerd Font codepoint** in `row.glyph` (NOT an `assets/icons/` basename — the delegate renders `glyph` as `Text` and hides the `IconImage` when it is set), and **no coordinates/app-ids/window-ids are ever displayed**: the detail is the window count, or the title when there is one window. Enter focuses that app's focused window (`NiriService.focusWindow`). Glyphs are written as `\uXXXX` escapes and were each verified present in JetBrainsMono-NF by rendering — pasting the raw PUA character put `E755` in the file where `E795` was meant. QML property names must start lowercase (`gTerminal`, not `G_TERMINAL`) or the whole config fails to load and **quickshell does not start**.
- **`Ctrl+Space` is web search, and Quick Look moved to `Ctrl+Alt+Space` (2026-10-05)**. `Ctrl+Space` → `qs -c sunset ipc call launcher websearch` → `Launcher.websearch()`, which calls `open()` and *then* `applyPrefix("@")` — the order is load-bearing, because `open()` resets `query` to `""` and would wipe a prefix seeded first. There is no web-search component: it is the launcher's existing `@` prefix (`rebuild()`'s `prefixKind` table maps `"@"` → `kind: "web"`), so all nine site bangs and the `xdg-open` in `WebProvider.activate()` are unchanged code. `applyPrefix()` was **extracted** out of the `;`-mode row branch so the mode rows and this keybind share one copy of the debounce handling instead of two — do not re-inline it at a second call site. Quick Look was `Ctrl+Space` before this and its two key handlers (`searchInput` **and** `appList`, both needed — the preview works with either holding focus) now test `ctrl && alt`. The `launcher preview` **IPC verb kept its name**: it names the action ("preview a file"), not the chord.
- **The launcher has a contextual right-click menu, and pinning (2026-10-05)**. Right-click a row, or press **F10** / the Menu key, for a menu whose items depend on the row's `kind`; right-click the search box or the space below the list for the beginner "how to use this" menu. Four things here are not obvious and each was a plausible silent break:
  - **`F10`/`Qt.Key_Menu`, NOT `;`.** `;` was the obvious choice and is **already the Modes prefix** (`rebuild()`'s `prefixKind`), so it cannot be both; `F10` is unbound in `niri/binds*.kdl`, so it needs **no compositor bind** and must NOT get one (the key handler already fires, and a bind would make it toggle twice). Handled in **both** key handlers (`searchInput` *and* `appList`) — one alone is a feature that dies whenever focus happens to sit on the list.
  - **The menu is hosted by `ContextMenu.qml`, not by a child of the launcher card.** It is a top-level layer-shell surface, so it can position in screen coordinates and take Exclusive keyboard focus. A child of the card could do neither, and would have to duplicate the whole card. `Launcher.qml` therefore **emits `rowMenuRequested(items, x, y)`** and `shell.qml` routes it to `contextMenu.openRow()` — a signal, not a direct call, because **two sibling Scopes cannot read each other's properties**. That routing is a **`Connections { target: launcherLoader.item }`**, never an `onRowMenuRequested:` on the `LazyLoader` itself: a `LazyLoader` exposes only its own signals, so such a handler compiles, logs `no signal of the target matches the name`, and never fires (the same silent-dead-handler trap as `Pipewire.nodeAdded` in `MicService`).
  - **The launcher's `focusTimer` must YIELD while the menu is open**, or it rips focus back to the search input and the menu's own Up/Down/Enter go dead. The handshake is `markMenuOpen()` on open and `markMenuClosed()` when `ContextMenu.isOpen` flips false — **driven by the shell, not a timer**: a fixed delay hands focus back while the menu is still on screen. Guarded on `menuKind === "launcher"` so a desktop/bar right click while the launcher is open cannot trigger it.
  - **`op` crosses a process boundary, so both halves are closed allowlists.** `ContextMenu.runLauncherOp` execs `qs … launcher rowMenuItem <op>`; the shell shim dispatches it onto `Launcher.rowMenuItem`, which re-checks the op before acting and calls **the same function the matching chord calls** (`activateCurrent` / `togglePreview` / `revealCurrent` / `copyCurrent` / `terminalCurrent` / `deleteCurrentBookmark` / `togglePinCurrent`). There is deliberately **no second implementation** of "reveal a file" to drift, and the launcher menu cannot execute a desktop-menu command (`lock`, `restart-shell`) because it uses its own `op`/allowlist rather than `fn`/`runOp`. `scripts/test_launcher_row_menu.py` lifts the real functions out of the QML under `node` and pins both halves — a name in one and not the other is an item that renders and then silently does nothing.
  - **Pinned rows** (`Pin to top` / `Unpin from top`) persist in `~/.local/share/niri-setup/launcher-pins.json` (FileView + `setText`, the `BookmarksProvider` precedent — **never tmp+rename**, the inode-watch rule) and are emitted by `pushPinnedRows()` into their own `Pinned` section **above** Controls. Keys are `app:<desktop-file-id>` / `control:<row name>`, **not indices** — `controlEntries` order is data and has already moved once, and an index pin would silently repoint. An "action" row resolves to its parent app so pinning an app keeps its action rows with it. Pinned rows are a **duplicate, not a move**: Applications stays the complete alphabetical list, and typing shows no pinned block at all, so a search can never return the same app twice. `reconcilePins()` drops a pin whose app is uninstalled.
- **`$NIRICONF`** paths appear in `binds.kdl`, `spawn-at-startup.kdl`, `waybar/config`, `waybar/style.css`, and 8 `scripts/*.sh` files. `setup.sh` replaces it via sed.
- **Auto-wallpaper daemon** (`scripts/auto-wallpaper.sh`) manages its state in `.state/` (PID, queue, history, log). Supports `--stop`, `--status`, `--oneshot`, `--next`.
- **A PID file is not proof of a process — never trust `kill -0` alone.** `auto-wallpaper.sh` shipped with a stale PID file naming 993; the kernel had handed 993 to `at-spi-bus-launcher`'s child, so `kill -0 993` succeeded, `--status` cheerfully reported "Daemon running", and `--stop` would have killed an accessibility service. Both `auto-wallpaper.sh` and `custom-theme.sh` now match `/proc/$pid/cmdline` against their own name (`pid_is_daemon`) and clear the file when it does not. `scripts/test_auto_wallpaper.py` covers it.
- **`change-wallpaper-simple.sh` only picks the file; `wallpaper.sh` applies it.** It used to `cp` into `wallpapers/`, run a *second* magick decode for the canvas colour, and `pkill swaybg; swaybg &` — so it never ran `wallust-theme.sh` (auto theming silently kept the *previous* wallpaper's palette when you switched from the menu), skipped the downscale, and desynced the fingerprint/swaybg state `wallpaper.sh` owns. It now just walks the sorted library for next/prev/random and `exec`s `wallpaper.sh`.
- **`wallust-theme.sh` must never blank a variant.** It used to truncate each output file with `: >"$output"` *before* mapping, so one wallust hiccup replaced a good `theme-wallpaper-soft.json` with a zero-byte file — worse than a stale one, because `Theme.qml` rejects an empty payload and keeps the old palette, leaving the picker advertising a variant with no colours. A failed variant now leaves its file untouched, and the log says `PARTIAL ... failed: light:no-raw` instead of `OK` with three of four listed. wallust itself intermittently fails a family, so the test retries three times before judging distinctness.
- **Waybar is legacy (rollback session only)**: `reload_style_on_change: true` still live-reloads CSS when waybar runs; config changes need `pkill waybar; waybar -c ~/niri-setup/waybar/config -s ~/niri-setup/waybar/style.css &`. Neither applies to the live quickshell session.
- **Quickshell sunset is the live shell**: `quickshell -c sunset` (0.3.1), spawned as `QT_QPA_PLATFORM=wayland NIRI_SETUP_HOME=<repo> quickshell -c sunset`. Waybar + dunst are stopped; `waybar/` is rollback gold only.
- **Quickshell config is a SYMLINK**: `~/.config/quickshell/sunset -> <repo>/quickshell/sunset`. QML edits go live on quickshell restart (`Mod+Shift+Q`, or `pkill quickshell; quickshell -c sunset &`) — no niri reload needed.
- **Popup/launcher toggles go through IPC**: `qs -c sunset ipc call <target> toggle` with targets `bluetooth | calendar | capture | clipboard | launcher | power | settings | volume | wifi | wallpaper | wallpaper-menu | notifications | themes | sessions | whip | menu | osd | weather`, plus `now-playing` (`toggle | open | close | download <mode> <quality> | downloadUrl <mode> <quality> <url> | loop | shuffle | pin`) and `screenshots` (`toggle | open <path> | openVideo <path> | recordStart <path> | recordStop | close`). Bar buttons and `binds-quickshell.kdl` (`Mod+Alt+*` for launcher/DND/wallpaper/**wifi**/themes/sessions/**screenshot**, `Mod+Shift+Q` restart) use this.
- **The screenshot utility is `CaptureBar.qml`, one panel holding all eight capture tools** (region / window / screen / scroll / record / OCR / screenshots folder / videos folder, plus Unpin). **Five things open it**, and every one of them must keep working: the bar camera pill (`CaptureWidget.qml`, left toggles / right shows, both `capture` IPC), `Mod+Shift+5` (`binds.kdl`), `Mod+Alt+Shift+S` (`binds-quickshell.kdl`), the launcher **Screenshot** control row (`Launcher.qml` `controlEntries`, `ipcTarget: "capture"`), and the **Screenshot** row in **both** `ContextMenu.qml` menus (`desktopItems` + `barItems`, `fn: "capture"` → `runOp` allowlist arm). A sixth, the `;` **Capture** mode in `ModesProvider.qml`, is a mirror of the control row. Three things about it that are not obvious and will silently look fine while being wrong:
  - **`WlrLayershell.keyboardFocus` must be `Exclusive`.** It was `None`, and that is *why* the panel was mouse-only for its whole life: a `FocusScope` on an unmapped surface never receives a key, so every arrow-key handler in the file was dead code that looked correct. There is no warning and no log line — the menu simply ignores the keyboard. If you add nav to any popup, check this first.
  - **It must collapse BEFORE it spawns the tool** (`run()` sets `isOpen = false`, then starts the `Process`). With the card now keyboard-mapped it is genuinely on screen, so a capture started while it is open would photograph the menu itself.
  - **Every row goes through `scripts/screenshot.sh`, never a bare `flameshot gui`.** The bare form skips the two things that make a capture useful: it never `wl-copy`s the image and never pops the OCR/Copy/Open/Delete pill, so the `;` **Screenshot** row used to disagree with the `Mod+Ctrl+S` bind while both claimed to be "screenshot". The three scripts are the whole contract: `screenshot.sh region|window|screen` → `screenshots open <path>`, `scroll-screenshot.sh` (bare = start/stop), `record-screen.sh toggle`. The `Print` family is deliberately **not** routed through them — niri's built-ins stay fast and silent, so they save a file with no clipboard copy and no pill. That asymmetry is intentional.
  - The 1–8 digits MOVE the selection rather than running the action: a mistyped digit must not start a screen recording. The row numbers and the digit keys share one function (`actionNumberFor`) so they cannot drift apart, and both skip the two separators.
- **The 15 popups are `LazyLoader`s, and `shell.qml` owns the IPC surface** (memory work, 2026-10-03). `shell.qml` no longer instantiates them; each is `LazyLoader { source: Qt.resolvedUrl("components/XPopup.qml") }` built on first use and **torn down 600ms after close** (`unloadDelay`, so exit animations finish). Measured: eager 208MB → lazy 177MB at rest, converging (253 vs 259MB) once you have actually opened everything — the saving is exactly the popups you never open, so it is never worse than eager. Two things that are **not** obvious and cost real time to rediscover:
  - **`LazyLoader.active` is asynchronous.** Flipping it does not make `item` available in the same tick, so no IPC shim may "activate then call". `dispatch()` parks the call in a `pending` map and each loader's `onItemChanged` replays it via `runPending()`. This is also why lazy-loading only the inner `PanelWindow` was rejected: it keeps the file compiled (measured *worse*, 176MB) and forces async-aware fixes at ~29 cross-boundary id references, several reachable with the popup closed.
  - **An IPC verb is not necessarily the root method it forwards to.** The shims are a verb-for-verb mirror of each popup's own `IpcHandler`, and the names differ in three places: `themes set` → `runItem`, `themes auto*` → `Theme.setAuto/toggleAuto` directly, `calendar pomo*/timerPause` → `PomodoroService` directly (a keybind must not build a 1000-line window it never shows). `wallpaper dbg` has **no** shim: it drives a Process declared inside the deferred window, is referenced by no bind, so it only answers once the picker has been opened. When a popup loads, its own `IpcHandler` registers and quickshell logs a benign "another handler is registered for target X" — the shim wins, which is what makes `dispatch()` authoritative. **Adding an IPC verb to a popup means adding it to the matching shim in `shell.qml`.**
  - Eager on purpose, do not lazify: `Toasts` (owns `org.freedesktop.Notifications`), `Osd` (340x52, keypress-driven), `ContextMenu` (owns the `sunset-desktop` input plane that must be mapped from startup). Their `notifications`/`osd`/`menu` targets live in their own files.
- **Two features left quickshell on 2026-10-02 — don't rebuild them**: `SettingsCenter.qml`, `HelpCenter.qml` (+ its `?` launcher mode / `HelpProvider.qml`) and the `WallpaperProcessEditor.qml` child pane were all deleted. Settings is now `scripts/gnome-settings.sh` (`Mod+Alt+S`: `XDG_CURRENT_DESKTOP=GNOME` + gtk-nocsd, forwards args so `gnome-settings.sh network` works) and help is `help/index.html` via `scripts/open-help.sh` (`Mod+Alt+H`, Brave `--app` window with its own profile, re-run toggles it shut). All three stay reachable from the launcher control rows (`Settings`, `Help & Guide`) plus `Mod+Alt+S` / `Mod+Alt+H`; the context menus keep only `Help & Guide` (Settings/Quick Settings rows were removed 2026-10-03). The `Mod+Alt+Shift+H` bind is gone, `Mod+Alt+H` is the guide. The launcher control rows carry `cmd` (run via `sh -c`) instead of `ipcTarget` for those two. Wallpaper knobs stay on `scripts/wallpaper-process.sh` — no GUI.
- **The custom palette has a GUI now (2026-10-03)**: `Mod+Alt+Shift+T` (Mod+Alt+T is the picker) and the launcher row "Custom Editor" run `scripts/custom-theme.sh`, which starts `scripts/custom-theme-server.py` on **127.0.0.7** and opens `help/custom-theme.html` in a Brave `--app` window; re-running toggles both shut. It edits all 11 tokens with a live preview and per-token contrast readouts, "start from" any existing palette, Apply / Save-without-switching / Revert / Defaults, and `Ctrl+Enter` applies. Three traps, all deliberate: (a) the page's own chrome is a **fixed neutral dark**, not palette-derived — an editor that themes itself moves the background while you judge a colour; (b) the server writes `theme-custom.json` **in place, never tmp-then-rename**, because quickshell watches it by inode and a rename silently kills the watch (the editor would save and nothing would change); (c) it carries a **token** in the URL and demands it in an `X-Theme-Token` header on POST — loopback is reachable from any page in the browser, so without it any site could repaint the desktop. It binds **127.0.0.7 rather than 127.0.0.1** because Chromium derives the window app-id from the host and `niri/rules.kdl` already pins `brave-127.0.0.1__-Default` (legacy volume popup) to 400x440. The server deliberately does **not** run `sync-external-theme.py`: that reads `active-theme.json`, which is the shell's *output*, so calling it from the server races the shell's own publish and pushes the previous palette. Reachable from the launcher control rows; the context menus keep only `Help & Guide`.
- **Right-click menus live in `components/ContextMenu.qml`** (one component, two item sets): desktop right-click opens the desktop menu at the cursor, bar right-click opens the bar menu below the bar at the click x (`Bar.qml` emits `contextMenuRequested(x, y)`, routed in `shell.qml`; widgets that claim the right button — VolumeWidget mute, Pomodoro — keep it). The **desktop input plane** is a transparent `sunset-desktop` surface on the layer-shell **bottom** layer (above swaybg, below windows): it eats clicks on wallpaper gaps only, and niri-level binds (incl. `WheelScroll*`) still win because the compositor intercepts them before the surface. Menu rows dispatch via `qs` IPC or a fixed command allowlist; `menu` IPC target: `openDesktop | openBar | open | close | toggle`.
- **Dynamic theming is a pipeline, and every stage is load-bearing**: `services/Theme.qml` holds the 11 taste.md tokens and 15 palettes; `scripts/wallust-theme.sh` extracts four **different** wallust palette families (`dark`/`darkcomp`/`softdark`/`light`, each in its own throwaway config dir so they can run concurrently) from the wallpaper into `theme-wallpaper*.json`, which `Theme.qml` watches live via `FileView`. `Theme.qml` publishes the active palette to `~/.local/share/niri-setup/active-theme.json`; `scripts/palette.sh get` (11 `KEY=RRGGBB` lines, no `#`) is the reader contract for anything outside quickshell. **If a surface hardcodes a hex it silently stops following the palette** — that was the actual state of `Launcher.qml`, `ClipboardPopup.qml`, `Toasts.qml`, `tmux/tmux.conf`, both `alacritty/*.toml`, `niri/layout.kdl`, `help/index.html` and the stroke icons, all stuck at Sunset Orange while the bar showed a wallpaper palette. Three traps that made it look deliberate:
  - **An alpha is not a colour.** fuzzel's `background #000000f2` and dunst's `#000000e6` mean "bg at 95%/90%", not black. Use `Theme.withAlpha(Theme.bg, 0.95)`; a literal `#f2000000` freezes that surface. Likewise text *drawn on* an accent fill is `Theme.onAccent`, which is **measured** (whichever of
    `bg`/`text` has more contrast against `accent`) — `Theme.bg` is wrong for about half of all
    palettes, and two wallpaper palettes had *no* colour reaching 4.5:1 on their accent, so a
    selected launcher row was genuinely unreadable. Use `onAccentMuted` for the secondary line
    inside a selected row. Every accent-filled surface must use these: `Launcher.qml`,
    `ClipboardPopup.qml`, `ThemePicker.qml`, `WallpaperMenu.qml`, `Workspaces.qml` (the active
    workspace pill in the BAR), `QuickSettings.qml`, `SessionEditor.qml`.
  - **Legibility is enforced, not requested.** `Theme.legibility()` pushes every palette — the 12
    hand-written ones, the 4 wallust ones, and whatever the custom editor saves — to the contrast
    floors in `scripts/colorlib.py` (`FLOORS`/`FLOOR_ORDER`, duplicated in `Theme.qml` because QML
    cannot import Python; `scripts/test_wallust_palette.py` parses the QML and fails on drift).
    `wallust-palette.py` runs the same table before writing, so the picker swatches, `palette.sh`
    and the external sync all read the numbers the shell will actually draw. Two traps: the
    binary search must test the **rounded 8-bit** value (searching the float and rounding lands a
    hundredth under the target, which is how the accent kept publishing 4.49:1 against a 4.50
    floor — hence `floorEps`), and there must be **no "keep whichever is better" fallback**:
    `at(1)` trivially has the most contrast so the comparison is always true and it collapses
    every colour to pure black or white.

  - **`PwNodeType` is a BITMASK, not the flat enum QML exposes.** qmltypes advertises a 0..12 list, but the wire value is flags: the mic device is `9` (Audio|Source), a capture client `13` (Audio|Stream|Source), the speaker device `17`, playback `21`. - **yt-dlp must never outlive `download-track.sh`, and a bash trap is not enough** (2026-10-04). Measured a yt-dlp still running **2h07m** with `~/Music` open, reparented to init, long after the card had flashed its result. Cause: the script backgrounds yt-dlp and traps SIGTERM, but **tearing a QProcess child down does not give bash a chance to run its trap** — restarting quickshell (`Mod+Shift+Q`) kills the script outright and the backgrounded grandchild survives. So the guarantee moved into the child, via `scripts/run-yt-dlp.py`: `os.setsid()` (its own process group, so the trap can signal ffmpeg post-processors along with it) plus `PR_SET_PDEATHSIG=SIGKILL` (the kernel kills it whatever the cause). Verified with `scripts/test_download_track.py`, which SIGKILLs the whole process group mid-download and asserts the grandchild is gone. One trap in the guard itself: **handing `execvp` a bare `sys.argv[1:]` eats the URL into argv[0]** — yt-dlp parses `sys.argv[1:]` as options, so every single download then failed with "You must provide at least one URL" regardless of what was being downloaded.
- **Downloads can be URL-based, and `scripts/clean-url.py` is the only thing that decides what a link means**: `download-track.sh <mode> <quality> [title] [artist] [url]` uses `url` as the yt-dlp target when given, else `ytsearch1:"<artist> <title>"`. The link comes from two places — the popup's download-menu field (paste from the clipboard runs the text through `clean-url.py`, so the field shows the canonical URL, not the junk; "Use this track's link" when `MediaService.trackWebUrl` exists) and `qs -c sunset ipc call now-playing downloadUrl <mode> <quality> <url>` (mirrored in the `shell.qml` shim, which builds the popup if it is closed). The CLI contract is one canonical URL on stdout, exit 1 + reason on stderr, and `scripts/test_clean_url.py` pins it. Four traps, all load-bearing: (a) **a link that cannot be canonicalised is a HARD failure (exit 1, `STATUS failed unusable link: …`), never a fallback to the search** — falling back answers a different request than the user made, and they find out when the wrong video lands in `~/Music`; (b) **a pasted link passes NO title/artist, so yt-dlp keeps the video's own tags and filename** — forcing the MPRIS title would file a pasted link under whatever happened to be playing (the same reason trap (b) above makes the *search result's* name win); (c) **only an `http(s)` `xesam:url` counts** (`MediaService.trackWebUrl`) — Chromium publishes none, mpv publishes a `file://` path to the local file, Spotify a `spotify:track:` URI, so a non-empty `metadata["xesam:url"]` is not a downloadable link; (d) **the URL field does NOT take focus when the menu opens**: a focused `TextField` eats Space and ←/→, which are this card's play/pause and prev/next. It also must not be `text: root.dlUrl` alone — the two-way bind needs `onTextEdited` writing back, or typing never reaches the property the download reads.
- **Duplicate validation after every download** (`music-dedup.sh`): a signature per track (size + md5 of the first and last 256KiB — no full decode) cached in `~/.cache/niri-setup/music-index.tsv`, rebuilt only when the library file COUNT moves (mtimes change for unrelated reasons, e.g. a tag rewrite). Match order is name → normalised name → signature → same-size + same title/artist tags, and only the same-size candidates ever reach ffprobe. A match **deletes our new file and keeps the existing one**, then says so in a notification. **The signature is the dedup key, so the index append must check for it first** — a blind append listed the same file again on every download (the rickroll test file appeared twice within one run). This is also what catches the real duplicate case: two different videos of one song download to two different filenames.
- **Media sources / switching** (`services/MediaService.qml`): auto-pick stays the default (playing > paused > first), but `pinnedDbusName` holds a *manual* pick that survives another player starting and is released when the pinned player loses its track or leaves the bus (`releaseSource()` clears it explicitly) — otherwise the shell latches onto a dead player. `sources` is the live list of players holding a track (elements are the real `MprisPlayer` objects, so rows are reactive without polling); `sourceName()`/`stateLabel()` hand the UI plain strings so no component needs the Mpris import. The card shows one segment per source only when 2+ exist, `S` cycles. **Qt trap:** plain `Row` has no `horizontalAlignment` (RowLayout-only) and `Flow` wraps — the switcher is a fixed-height `Item` with a `Row` centred by anchor and each segment capped at `width/count`.
- **Repeat / shuffle / pin live in the card, and both MPRIS modes are per-player (2026-10-04)**. `MediaService` gained `canLoop`/`canShuffle`/`loopTrack`/`loopPlaylist`/`shuffleOn`, `cycleLoop()`, `toggleShuffle()`, `sourcePinned` and `togglePin()`; the card renders an `NpToggle` row under the transport buttons and takes `L` repeat / `X` shuffle / `P` pin (stop moved `X`→`E`). IPC: `now-playing loop | shuffle | pin`. Five things that are not obvious and were all hit here:
  - **Support is not guessable from the metaobject — ask the property.** Brave's MPRIS exports **no `LoopStatus` and no `Shuffle` at all** (a raw `dbus-send Properties.Get` on the bus fails outright for both), so quickshell reports `loopSupported`/`shuffleSupported` false. mpv exports both and honours them. Hence each button is `visible: MediaService.canLoop/canShuffle`: a row rendered unconditionally is dead controls that look live, and the hint line is built from the same flags so it never advertises a key that does nothing.
  - **Verify a property round-trips before trusting it, and mind the bus name.** mpv initially looked like it ignored every write — it did not. `play-library.sh` starts a *new* mpv per run and the old one lingers, so `playerctl --list-all | tail -1` handed back a name that had already been replaced (`ServiceUnknown` on the next call). The lesson generalises: pin the bus name once (`p=$(playerctl --list-all | grep '^mpv' | tail -1)`) and **sleep ~1s after a Set before reading back** — mpv applies it asynchronously, so an immediate read returns the previous value and looks like a silent failure. `dbus-send` needs `variant:boolean:true` for Shuffle; sending it as a string gets `Expected type "b" but got "s"` and appears to be a no-op.
  - **A toggle's "on" state must NOT be an accent fill.** `Theme.onAccent` measures a *Text* foreground, but **QtQuick's `Image` has no `color` property** — binding one does not tint the glyph, it fails to load — so there is no way to repaint a baked neutral SVG for a bright background. Filling the pill with the accent produced exactly the regression the icon set exists to prevent: a dim-weight icon dumped on a bright accent, reading as a grey smudge. `NpToggle` keeps the pill transparent/`row` and carries state with an **accent underline** (the `Workspaces.qml` active-pill trick) plus a **shape swap** — three glyphs for repeat (`repeat-off` / `repeat-one` / `repeat`).
  - **Off-state glyphs are authored on the `dim` hex** so the generator maps them to `iconMuted`, the set's reserved "off" step. This is what `ICON_ROLE_BY_SUNSET_HEX` calls load-bearing, and a new off/on pair has to keep it: the shape alone must distinguish "muted" from "working", because `#555555` is the ONLY role with its own step.
  - **`releaseSource()` had no caller for its whole life.** `pinnedDbusName` is set by `selectSource()`, so using the source switcher once latched the card onto that player permanently — that is what made the switcher feel sticky. The pin toggle is the missing unpin path, and it is deliberately **hidden unless `multipleSources`**: with one player there is nothing for auto-pick to steal the card from, and a protection that cannot be tested should not be advertised.

## Chromium PWA titlebar (do not "fix" this by reverting)

Installed Chromium PWAs (WhatsApp, YouTube) used to show a stubborn strip above
the page with `▭ ▣ ≡ ─ ⧉ ✕` on the right. That strip is **Chromium's own
client-side titlebar**, not the quickshell bar. Root cause, verified with
`WAYLAND_DEBUG=1`:

```
zxdg_toplevel_decoration_v1#45.set_mode(2)   # 2 = server_side
zxdg_toplevel_decoration_v1#45.configure(2)
```

niri 26.04 **does** advertise `xdg_decoration_manager_v1` and confirms
server-side decorations, but it deliberately draws no decoration bar — it
relies on the client omitting CSD (`prefer-no-csd`). Installed PWAs
(`--app-id=`) don't omit it, so they keep the strip. `prefer-no-csd` and
`open-fullscreen` do **not** fix it: niri asks the client, and Chromium ignores
both (fullscreen is refused outright on these windows, and it would hide the
bar anyway).

The only working lever: launch the PWA with **`--app=URL` instead of
`--app-id=`**. That form omits the titlebar. Verified side by side in one
session — `--app=https://example.com` has no strip, `--app-id=...` does.

So the desktop entries in `~/.local/share/applications/` were rewritten:

```kdl
# brave-<32-char a-p extension id>-Default.desktop  (generated by Chromium)
Exec=/opt/brave-bin/brave --profile-directory=Default --app=https://web.whatsapp.com/
```

Costs of `--app=URL`, accepted deliberately: it is no longer a *real* PWA, so
the badge count and Chromium's unified PWA notification integration are lost
and the login state is a normal profile tab. `?` must be quoted in `Exec`
(`desktop-file-validate` rejects it bare). The old `--app-launch-url-for-
shortcuts-menu-item=` actions were replaced with plain per-action `--app=` URLs.

**To add a new PWA**: rewrite its desktop entry to `--app=<url>`, and read the
real start URL out of `Sessions/Apps_*` if you need it (`Preferences` has no
`start_url`/`scope` keys). The PWA id is the same across Brave/Chromium/Chrome/
Edge/Vivaldi/Opera, so the `rules.kdl` match works for any of them without
edits. Do **not** re-add `--app-id` — that brings the titlebar straight back.

Window naming: these windows' app-ids are synthetic and unreadable, and
`WindowWidget`'s last-dotted-segment fallback printed the raw
`brave-agimnkijcaahngcdmfeangaknmldooml-Default`. `isChromiumAppWindow()` now
detects both shapes (`-<a-p>{32}-` for installed PWAs, `-<host>__-` for
`--app=URL`) and the bar shows the page title instead.
